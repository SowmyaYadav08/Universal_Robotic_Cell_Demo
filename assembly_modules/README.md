# Assembly Module Hub

## One entry dashboard

Open **assembly_modules/index.html**. Select a module in the top dropdown; that
module's monitor opens within the same page. The module selector remains visible
while viewing reports or demos. The Reports & demo menu changes with the selected
module. Monitor returns to its issue table. Open this view in a new tab is optional.

Only existing reports are enabled. Prefilter and Tube Interface recovery demos
are explicitly unavailable; no Light Localizer animation is substituted. Their
video libraries are previews, not defect-detection reports. Data and files remain
separate even though the interface has one entry point.

The page is already rebuilt for current files. Future run_all.py runs refresh
availability automatically. After generating a module independently, run
`python assembly_modules/build_hub.py` to refresh which reports are available.
Routing uses local HTML frames and needs no server or external service.

This folder groups all three modules without mixing their scenarios or outputs.

```text
assembly_modules/
  index.html                 Links to each module
  run_all.py                 Runs each module independently
  light_localizer/
    run_demo.py               Uses existing recovery_demo implementation
    outputs/                  Light Localizer reports only
  prefilter/
    scenarios.py              Bearing scenarios only
    run_demo.py
    outputs/                  Prefilter reports and previews only
  tube_interface/
    scenarios.py              Tube Interface scenarios only
    run_demo.py
    outputs/                  Tube Interface reports and previews only
  shared/                    Common reporting and synthetic-operation utilities
```

Run from the workspace:

```powershell
python assembly_modules/run_all.py
```

Then open `assembly_modules/index.html`. There is no combined incident dataset.
Each module has its own events.csv, results.json and dashboard.html. Shared code
does not imply that process rules or training data are shared across modules.

To also generate separate approved video previews for the two new modules:

```powershell
python assembly_modules/run_all.py --previews
```

Or run a module independently:

```powershell
python assembly_modules/prefilter/run_demo.py --previews
python assembly_modules/tube_interface/run_demo.py --previews
python assembly_modules/light_localizer/run_demo.py
```

Existing Light Localizer commands and output paths remain available. Its primary
implementation stays in recovery_demo to avoid an inconsistent duplicate. Running
recovery_demo/run_demo.py now produces only its original 20 cases. Existing saved
reports are not deleted or silently regenerated by this reorganization.

Prefilter and Tube Interface use five explicitly synthetic cases each, with
module-specific stage assumptions. Their fault recovery policies and video
detectors remain unimplemented. The optional library command extracts pictures
only from approved recordings, locally. No model comparison or remote service is
involved. The DINOv2 experiment and its frozen snapshot remain unchanged.
